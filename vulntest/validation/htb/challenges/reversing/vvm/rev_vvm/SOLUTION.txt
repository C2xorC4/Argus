ARCHITECTURE
============
The "VM" is actually a clever obfuscation pattern:
- sub_401530 (setup): decrypts 24 small native x86_64 code blobs from
  data_405020..data_40553f using a 6-byte XOR key cycle
  [0x2a, 0x0b, 0x21, 0x21, 0x4d, 0x2a], mmaps each RWX, copies decrypted
  bytes, and stores function pointers at offsets in struct data_4074e0.
  Plus 4 native function pointers: sub_4012a0, sub_401320, sub_4013a0,
  sub_4013e0.
- sub_402870 (dispatcher): reads a 32-bit opcode index `i` from the
  bytecode at data_405540, and calls funcs[i] with shared registers:
  rdi = pc (bytecode base), rsi = &pc, rdx = stack base (data_406220),
  rcx = sp pointer (data_406200), r8 = funcs table.
- The handlers (the "blobs") implement a 28-opcode stack machine.
- 0x1c is HALT.

CHECK ALGORITHM
===============
1. Print "What is the password: " (built via PUSH_IMM/arith + PACK_BYTES n=22).
2. Read line from stdin (GETLINE).
3. Trim trailing newline; compute strlen.
4. Length check: ((strlen*6 - 12 + 4)/2 * 8 + 24)/10 == 76
   => strlen must equal 32.
5. Pack input into 8 uint32 chunks. Each chunk uses 4 bytes from input:
       chunk[i] = input[idx0] | input[idx1]<<8 | input[idx2]<<16 | input[idx3]<<24
   The index sets (in the order they appear on stack as b0..b3) are:
       chunk_indices = [
           [24, 14, 27, 15],  # c0
           [11, 7, 12, 4],    # c1
           [6, 9, 2, 18],     # c2
           [19, 13, 20, 26],  # c3
           [28, 16, 23, 8],   # c4
           [3, 30, 21, 22],   # c5
           [25, 5, 10, 31],   # c6
           [29, 1, 0, 17],    # c7
       ]
6. ROL each chunk by a fixed amount (mapping c7..c0 -> r0..r7):
       r0 = ROL(c7, 15)
       r1 = ROL(c6, 19)
       r2 = ROL(c5, 7)
       r3 = ROL(c4, 18)
       r4 = ROL(c3, 12)
       r5 = ROL(c2, 20)
       r6 = ROL(c1, 14)
       r7 = ROL(c0, 7)
7. Compare each r_i against a target constant; any mismatch -> "Incorrect".
   Targets:
       r0 == 0x2a239824
       r1 == 0x8a73ea61
       r2 == 0xba3cbd99
       r3 == 0xddbdd50d
       r4 == 0xf3444305
       r5 == 0x47272423
       r6 == 0x1517dd9c
       r7 == 0xb639b429

CRITICAL SIM DETAIL
===================
PUSH_IMM uses `mov edi, [rax]` (32-bit, zero-extending) — constants are
*unsigned 32-bit* on the stack, NOT sign-extended. This matters for the
final SUB-then-JNZ comparison, where the targets like 0x8a73ea61 must
match the 32-bit zero-extended ROL output rather than the signed Python
representation -1972114847.
